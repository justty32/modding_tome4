# Erebus — 分期與分工

← [README](README.md)

**✅ 2026-08-06 使用者拍板的順序：從上往下。**
先把**大世界地圖**該有的全部鋪好，再做中層，最後做下層。所有文明都做。

**為什麼這個順序對**（值得寫下來，因為它跟一般的「先垂直切片」相反）：

1. **大地圖是抄來的，最便宜。** 從 FFH 本體轉換（[09](09-source-mod-unpack.md)），
   不必發明地形也不必發明城市位置。
2. **它一鋪完，全部內容的清單就固定了。** 有幾個文明、幾座城市、各在哪、屬於誰——
   全部變成已知。**之後每一份工作都是「填一格」**，範圍可估、可派、可平行。
3. **玩家從第一天就能走遍整片大陸。** 即使很多門還關著，世界的骨架是完整的。

⚠️ **這個順序的代價是「一堆進不去的門」。** 對策寫死：
**內容還沒做的地點，就不要在大地圖上放入口格**——等它做好了才長出來。
寧可地圖上少一個標記，也不要玩家走過去撞一面空牆。

## 1. 分期

每一期都要能獨立 playtest。

### 第一階段：把上層鋪滿

| 期 | 內容 | Done when |
|---|---|---|
| **v0.1 骨架** | 新 worldmap zone + 登陸點 + 從 Eyal 進來的傳送門 | 走得進去、走得回來、`verify` 綠燈、**逐格走過連通性** |
| **v0.1.5 地基探測** ★ | **只做一件事：驗證「就地動態生成一張 zone 再進去」可不可行**（[02 §6](02-mechanics.md) 複驗項 7）| 有明確結論。**不成立就改設計，此時零成本** |
| **v0.2 鋪滿大世界地圖** ★ | 從 FFH 轉整張地圖；所有文明領地、所有城市位置、勢力範圍表、地形對映 | 整張地圖走得完；每座城市在正確座標；**任一格算得出它屬於誰、離哪座城最近** |

> **v0.1.5 是刻意插進來的。** 它只花一點時間，卻決定中層那套機制成不成立——
> **不要等到做中層才發現地基不對。**

### 第二階段：中層

| 期 | 內容 | Done when |
|---|---|---|
| **v0.3 AC 核心** ★ | 末日計數器：存檔、加減、門檻觸發、查詢面板 | 複驗項 1–3 全過；AC 30 的枯萎真的改變世界 |
| **v0.4 中層區域地圖** ★ | 「進入區域」技能、L1 生成、勢力範圍計算、臨時 zone 存檔與 LRU 淘汰 | 荒野格進得去；內容隨地形／勢力／AC 而變；**存檔往返與淘汰驗過** |
| **v0.5 軍團層** | L0 的軍團 → L1 戰場 → L2 遭遇的三層鏈（[02 §5.5](02-mechanics.md)）| 撞上軍團會進戰場、打得掉團隊、撤得了退；**軍團／團隊資料結構與所有者無關**（為未來的玩家軍團留路，[02 §5.5.3](02-mechanics.md)）|

### 第三階段：下層與量產

| 期 | 內容 | Done when |
|---|---|---|
| **v0.6 範本城市** ★ | **一座城市**照 [03 §1.1](03-content-model.md) 的八件套做到完 | 八件全到；資料表格式定案；**這一期證明格式撐得住** |
| **v0.7 法球與宗教** | 全部法球 + 全部教團 + 法力節點 | 任何職業都能取得並使用；AC 隨用球而動 |
| **v0.8+ 量產** | **一期一個文明（含它的全部城市）**，多隻 agent 平行 | 每座城市八件套齊全、各自 verify 綠燈、**接縫檢查過** |
| **v0.9 末日後段** | 四騎士、地獄地形、憤怒化身 | AC 80／90 真的改變地圖與遭遇 |
| **v1.0 三結局** | 終局 zone 與三條分支、平衡、文案收尾 | 三條都走得到、都有收尾 lore |

### 三個生死關

| 期 | 若失敗 | 退路 |
|---|---|---|
| **v0.1.5 地基探測** | 「無數的冒險」整套要換做法 | 預先定義 N 種區域地圖模板，依地形挑一張。效果打折但一定能動 |
| **v0.3 AC 核心** | 整個 addon 的世界變化都是假的 | 沒有退路，必須做對。存檔往返要驗透 |
| **v0.6 範本城市** | 量產的格式不對，愈做愈錯 | 只賠一座城市，重設計 [03](03-content-model.md) 的表 |

**v0.1.5 排在最前面就是為了讓失敗最便宜。** 那時候還沒有任何內容，改設計零成本。

## 2. 誰做什麼

| 工作 | 交給誰 | 理由 |
|---|---|---|
| v0.1 骨架、`init.lua`、`hooks/load.lua`、資料表格式定案 | **主 agent** | 格式定生死，且是所有人的共用檔 |
| **v0.1.5 地基探測** | **主 agent** | 這題的結論決定整個設計，不能外包 |
| **v0.2 地圖轉換腳本**（FFH 存檔 → ToME ASCII 地圖） | **sonnet** | 兩邊都是逐格文字，**純機械轉換**，正是 sonnet 的甜蜜區 |
| v0.2 勢力範圍表與座標校對 | **sonnet**，主 agent 複驗 | 量大但規則明確 |
| v0.3 AC 核心、v0.4 中層生成 | **主 agent** | 機制敏感、要複驗、動全域狀態與存檔 |
| v0.6 範本城市 | **主 agent 或 sonnet** | 這是範本，之後所有城市照它抄。品質要撐得住 |
| v0.8+ 每個文明的城市 | **一隻 deepseek 一個文明，可平行** | 純填表 + 抄範本，正是弱模型的甜蜜區 |
| 冒險模板的填表量產（[03 §1.2](03-content-model.md)） | **deepseek**，可以一直生 | 只填欄位與三段文字，格式錯了 lint 抓得到 |
| lore 與對白的量產 | **deepseek**，語氣護欄見 [01 §8](01-world.md) | 量大、規則明確 |
| 地獄地形的地面圖 | `agy` 生圖（地面圖不需要透明，最安全的一類） | 見 [assets.md](../../agent-driving/assets.md) |
| 中文文案定稿 | **一律使用者審** | 語氣、翻譯腔，AI 判斷不了 |
| 平衡與手感 | **一律使用者實機判斷** | 無頭測試證明不了好不好玩 |

## 3. 平行開工的四條硬規則

照 [CONTRACT.template.md](../../agent-driving/CONTRACT.template.md) 寫契約，並確保這四條在裡面：

1. **一個 civ 一組資料夾**，不准碰別人的。共用資料表由編排者定案，agent 只讀不寫。
2. **要掛 hook 寫進 `hooks/parts/<civ>.lua`**，不准改 `hooks/load.lua`。
   ⚠️ **編排者要先把迴圈載入寫進 `load.lua`**——這個機制目前還沒有任何 addon 實作過。
3. **`TOME_PLAYTEST_STATE` 每隻不同**，否則互相 `rm -rf`，症狀是假綠燈。
4. **相依性最高的最後跑**（劇情 ＞ 地城 ＞ 城鎮），它是整合哨兵。

**整合者（你）必須自己跑一次 verify 並主動檢查交界**——三隻各自綠燈、合起來是壞的，
本 repo 2026-08-01 實測過。

## 4. 每個文明的驗收清單（交件標準）

實作 agent 要能逐項回答，**八項全綠才算交件**：

| # | 檢查 | 怎麼證明 |
|---|---|---|
| 1 | `tools/lint.sh tome-erebus` 退出碼 0 | 貼輸出 |
| 2 | `tools/verify.sh tome-erebus` 綠燈、無 Lua Error | 貼輸出 |
| 3 | 城鎮 zone 進得去、**從入口逐格走到每個 NPC** | 不准只用 `changeLevel()` 跳 |
| 4 | 地城每層都下得去、底層守關者在 | probe |
| 5 | 每個 NPC 都有 `name`、都講得了話 | probe |
| 6 | 任務鏈從頭走到完成 | log |
| 7 | 至少一個任務真的改變了 AC | 前後數值 |
| 8 | 對白三檔（低／中／高 AC）都寫了 | 檔案檢查 |

## 5. 規模誠實話

原版 ToME 全部內容是 **52 個 quest、100 個 chat、89 個 zone**
（[orario spec §2](../orario-complete-design.md) 實測計數）。這是我們的比例尺。

使用者要的是**復刻全部**。粗估一下那是什麼量級：

| 假設 | 數字 |
|---|---|
| 文明 20 個，每文明 3–5 座城市 | **60–100 座城市** |
| 每座城市 1–4 個 zone（大城切區塊）+ 1–2 個周邊地城 | **200–400 個 zone** |
| 每座城市 2–3 手寫 + 5–15 模板冒險 | **400–1500 個 quest** |
| 每座城市 3–6 具名 NPC | **300–600 個 NPC** |

**這是原版 ToME 的 3–5 倍。** 講白話：**這不是一個 v1.0 能做完的東西，
它是一條長期產線。** 這不是勸退，是要據此決定做法：

1. **v1.0 的定義要改**：不是「全部做完」，而是「**產線跑順，且有一個文明的完整成品當範本**」。
2. **每座城市獨立可玩、獨立出貨。** 沒做的地方在大地圖上就是還沒開放的區域，不是斷裂。
3. **架構天生可以無限加**——每加一座城市就是再跑一次同樣的八件套。
   所以真正要做對的是**前五期**（骨架、範本城市、AC、法球宗教、軍團），
   那之後就是燒 token 的重複勞動，正是 deepseek 該做的事。
4. **地圖從原作抄、素材從原作抽**（[09](09-source-mod-unpack.md)），
   這省掉的是整個計畫裡最貴的「發明內容」那一段。
