# Erebus — 機制與引擎對應

← [README](README.md)｜世界觀見 [01](01-world.md)

> ⚠️ **本份寫於辦公室 Windows 機（`vendor/` 空、無 luajit），沒有複驗任何行號。**
> 下面出現的引擎結論**全部搬運自 `docs/knowledge/` 或既有 spec**，並標明出處。
> **沒有一條是本份新查的。** §6 是複驗清單，到 Manjaro 第一件事就是跑它。

## 1. 全部機制只有五件事

| # | 機制 | 一句話 | 成本 |
|---|---|---|---|
| **1** | **末日計數器（AC）** | 一個 0–100 的全域數字，世界照它改變 | 低（核心便宜到不可思議）|
| **2** | **區域 zone** | 大地圖上的空白格子，用技能就地生成一張中尺度地圖 | **中高（但回報最大）** |
| **3** | **法球（Mana Spheres）** | 找到法力節點 → 調出一種球 → 授予對應技能樹 | 低（用現成的授予技能樹機制）|
| **4** | **宗教** | 加入一個教 → 授予教團樹 + 陣營友好／敵對 | 低 |
| **5** | **地獄地形** | AC 高到門檻，世界地圖的格子逐塊替換 | 中 |

**這五件事互相咬合**：用惡球會推高 AC；AC 高會長出地獄地形、也會改變區域 zone 生成什麼；
加入 Ashen Veil 推高 AC、加入 Order 壓低。**力量與代價掛鉤是 FFH 的精神，不要拆開。**

## 2. 末日計數器：這個 addon 的心臟

### 2.1 存哪裡

```lua
game.party.erebus = {
  ac = 0,                    -- 0..100
  triggered = {},            -- 已觸發過的門檻，避免重複觸發
  horsemen = {},             -- 已降臨的騎士
}
```

**✅ 2026-08-06 使用者拍板：AC 跟著存檔走。**
同一個存檔內換角色，AC 自然延續；不同存檔各自獨立。
**所以不必做跨存檔持久化**——只要它隨存檔正確序列化就好。

放 `game.party` 正是為此：它隨存檔序列化，且不是 actor 專屬。
先例：[orario spec §5.5](../orario-complete-design.md) 的眷族欄位就是放 `game.party`。

### 2.2 什麼會動這條數字

**這張表就是玩家的道德帳本，也是實作 agent 要填的表。**

| 推高 AC | 壓低 AC |
|---|---|
| 使用惡性法球的天賦（Entropy／Death／Shadow） | 使用善性法球（Life／Law／Sun）|
| 加入 Ashen Veil；完成 Sheaim 的任務線 | 加入 Order／Empyrean；完成 Bannor 的任務線 |
| 屠殺中立 NPC、洗劫聚落 | 淨化被腐化的地點、擊敗惡魔 |
| 讓某些 boss 活著到期限 | 建成盧諾塔之壇（大幅壓低）|

**每一筆變動量寫在資料表裡，不寫死在程式碼裡**——這樣調平衡不必動 Lua。

### 2.3 門檻怎麼改變世界

**這是本設計最划算的一段：一條數字驅動整個世界的變化，而每個門檻只要換文本與生成表。**

| AC | 事件 | 實作上實際要做什麼 |
|---|---|---|
| 30 | **枯萎** | 野外生成表加入病變版怪；部分具名 NPC 標記死亡；城鎮對白換一組 |
| 40 / 50 / 60 / 70 | **四騎士**依序降臨 | 每次在世界地圖生成一個**遊蕩的高難度 zone／遭遇**（見 §5）|
| 80 | **地獄地形蔓延** | 世界地圖格逐塊替換（§5）|
| 90 | **憤怒化身現世** | 開啟最終 boss 的入口 |
| 100 | **末日** | 觸發終局：世界毀滅結局（[01 §7](01-world.md)）|

⚠️ **門檻只能單向觸發一次**（用 `triggered` 表擋），否則 AC 在門檻上下震盪會反覆放事件。

### 2.4 玩家怎麼知道現在幾點

- **數字**：一個小面板／一條指令查得到（自訂 UI 見 `docs/knowledge/custom-ui.md`）。
- **徵兆**：NPC 對白隨 AC 分檔換一組。**這是文案的主要工作量**，也是弱模型最適合做的填表工作。
- **不要**把 AC 做成常駐在畫面上的血條。它應該是你**去查**才知道的東西。

## 2.5 區域 zone：把空白格子變成一場冒險 ★

**使用者 2026-08-06 定調。這是「無數的冒險」真正的引擎**，也是本設計最有價值的一塊。

### 2.5.1 三層，三種 zone，就這樣

**✅ 2026-08-06 使用者拍板：只用三層。** 不多也不少。

| 層 | 名稱 | 一格代表 | 上面活動的是 | 怎麼來的 |
|---|---|---|---|---|
| **L0** | **大世界地圖** | 一片地方 | **軍團／團體**（[§5.5](#55-大地圖上活動的是軍團不是個人)）| 一張，從 FFH 原作抄（[09](09-source-mod-unpack.md)）|
| **L1** | **中層區域地圖** | 一小塊地 | **團體，也有個人**。散落村落、營地、遺跡 | 就地生成 |
| **L2** | **實際活動地圖** | 實際的一格地面 | 個人、單場戰鬥。一般 roguelike 尺度 | **手寫**（城市區塊、地城）**或就地生成** |

**「進入區域」技能只在 L0 與 L1 可用**，而且只能對**純地形格**用
（有城市或地點的格子照舊按 `>` 進去）。

**L2 沒有「進入區域」。** 這不是硬性擋掉的，是規則自然收斂：
L2 的一格就是實際的一格地面——一棵樹、一塊石頭、一格草地，
**它不代表「一片地方」，所以技能沒有合法目標**。三層到此為止。

⚠️ **L2 有兩種來源，但它們是同一種 zone。** 城市區塊、地城是手寫的；
從 L1 鑽下來的是生成的。兩者在引擎裡沒有差別，玩家也不該感覺得出斷層——
這是「手寫內容」與「無限生成內容」接在同一個尺度上的接縫，**要特別注意風格一致**。

> 這一層填掉了「大地圖上百分之九十的格子都是路過用的」這個空洞。
> 每一格荒郊野外都變成可以進去的地方，而且內容是算出來的，不是手寫的。

### 2.5.2 生成內容由三件事決定

```text
區域 zone 的內容 = 地形 × 勢力範圍 × 世界狀態(AC)
```

| 輸入 | 來源 | 影響什麼 |
|---|---|---|
| **地形** | 該大地圖格的地磚（草原／森林／山地／沼澤／荒漠／地獄地形） | 地圖生成器、地貌、野生生物 |
| **文明勢力範圍** | 該格屬於哪個文明的影響圈、在核心還是邊陲 | 建築風格、居民種族、派系、語氣 |
| **城市勢力範圍** | 離哪座城市最近、屬不屬於它的轄區 | **散落的村落**、商隊、巡邏隊、該城的任務鉤子 |
| **AC** | 全域末日計數器 | 村落是興盛還是荒廢、遇到商隊還是劫掠團、有沒有地獄地形侵蝕 |

**兩層勢力範圍都要有**（文明的 + 城市的），因為它們解釋的東西不同：
文明決定「這裡的人是誰」，城市決定「這裡歸誰管、有沒有人住」。

無主之地（不在任何勢力範圍內）不是空的，是**另一種內容**：
盜匪、隱士、廢墟、野生的東西、以及最好的意外收穫。

### 2.5.3 具體長什麼樣

一張區域 zone 上會有：

| 元素 | 說明 |
|---|---|
| **村落／營地** | 小型互動點。幾個 NPC、一兩個商人、一兩個委託。**在城市勢力範圍內才會有** |
| **團體** | 巡邏隊、商隊、朝聖團、劫掠團、獸群。可打、可談、可跟 |
| **個人** | 旅人、逃兵、隱士、瘋子、傷者。**單獨的人只在這一層出現**，大地圖上沒有 |
| **地物** | 廢墟、法力節點、神龕、墳場、被燒掉的農莊 |
| **通往下一層的入口** | 洞窟、地窖、塔——通往真正的地城 zone |

### 2.5.4 臨時 zone 的壽命：存檔內保留，有上限，LRU 淘汰

**✅ 2026-08-06 使用者拍板。** 生成出來的臨時 zone **跟著存檔走**，
但**有數量上限**；超過上限就把**最久沒去過的**刪掉。

**臨時 zone 只有兩種**（L1 中層、L2 下層），**兩種的上限分開算**——
手寫的城市區塊與地城是永久的，不進這個池子。

```lua
game.party.erebus.regions = {
  L1 = { ["34,21"] = { seed = ..., last_visit = <turn>, pinned = false }, ... },
  L2 = { ["34,21/7,12"] = { seed = ..., last_visit = <turn>, pinned = false }, ... },
}
-- 兩個獨立配額：cap_L1、cap_L2。生成新的時只檢查自己那一池
```

| 規則 | 內容 |
|---|---|
| **保留** | 臨時 zone 進存檔。你回去時東西還在原地——沒清完的怪、沒開的箱子都在 |
| **上限** | **L1 與 L2 各有各的配額，分開計算、分開淘汰**。兩個都是設定值，要實測存檔大小才知道合理值 |
| **淘汰** | 生成新的時只檢查自己那一池；超過就刪該池 `last_visit` 最舊的。**每次進入要更新 `last_visit`** |
| **釘選不淘汰** | 已固化的具名地點、玩家手動標記的、有未完成任務指向的，一律 `pinned` |
| **被淘汰之後** | 用同一個種子重新生成 → **地形與佈局一模一樣**，但住民與掉落重置 |

> **為什麼要分開算**：L2 的數量天生比 L1 多得多（一張 L1 可以鑽出好幾張 L2），
> 共用配額的話 L2 會把 L1 洗掉，導致你回到剛探索過的區域卻發現整片地圖重置了。
> 分開算才能讓「中層是你認得的地方、下層是消耗品」這個直覺成立。

⚠️ **重生成會造成刷寶漏洞**（清空一格 → 等它被淘汰 → 回去再清一次）。
對策很便宜：**淘汰整張圖，但每格留一個極小的「已被清過」旗標**，
重生成時不再放獨特獎勵與具名敵人，只放普通野怪。旗標是幾個位元組，不影響存檔大小。

### 2.5.5 發現即固化

在臨時 zone 裡找到**有名字的東西**（一座村落、一個法力節點、一個地城入口），
就把它**登記回大地圖 L0 的那一格**——之後那格變成永久地點，直接按 `>` 進去，
不必再鑽兩層。同時該 zone 被 `pinned`，不受淘汰。

> **這條設計讓探索有意義**：你不是在刷隨機地圖，
> 你是在**把一張空白的大陸，變成一張有標記的大陸**。
> 而永久化的東西只有你真的找到的那些——世界的密度由玩家的腳程決定。

### 2.5.6 引擎對應（草案，全部待複驗）

| 要做的 | 候選做法 |
|---|---|
| 「進入區域」技能 | 一個**全職業天賦**，進入 Erebus 時自動學會。前例：`tome-crafting` 用 `ToME:birthDone` 讓全職業自動學會兩個天賦（`wf/session_log/2026-07-p2.md` 有記）|
| 就地生成一張 zone | 動態組出 zone 定義再 `changeLevel`。**這是本機制最不確定的一步**，見複驗項 7 |
| 生成器 | 用 ToME 現成的（Forest／Cavern／Roomer 等），依地形挑一個，不要自己寫地圖演算法 |
| 村落與團體 | zone 的 `npc_list` + spot／特殊房間，由 §2.5.2 的表算出來 |
| 固化回大地圖 | 把該格換成帶 `change_zone` 的地磚並存進世界狀態 |

⚠️ **回到同一格會不會拿到同一張圖？** 決定：**用「大地圖座標 + 世界種子」當亂數種子**，
所以同一格重進是同一張圖（在它被固化或世界狀態改變之前）。
這比「每次都不同」合理得多，也讓玩家可以回去找剛才沒清完的東西。

## 3. 法球 = 技能樹

FFH 的 21 種法球全部復刻。**✅ 2026-08-06 使用者拍板：一個法球會有多棵技能樹。**

### 3.1 一球多樹：依用途分，不依等級分

一個法球是一**組**技能樹（2–3 棵），切法是**用途**：

| 樹 | 做什麼 | 例（火球） |
|---|---|---|
| **塑形** | 直接的攻擊與操作 | 火矢、爆燃、火牆 |
| **召喚** | 叫出屬於這一球的東西 | 火元素、灰燼獸 |
| **銘刻** | 增益、詛咒、持續效果 | 武器附火、燃燒詛咒、抗寒 |

**不是每一球都有三棵。** 生命球可能只有塑形與銘刻，死亡球三棵都有，
律法球可能只有銘刻。**由該球在原作裡的性格決定，寫在資料表裡。**

### 3.2 取得與深化

| 步驟 | 引擎對應 |
|---|---|
| 世界上散佈**法力節點** | 一個 zone 內的互動格／NPC |
| 在節點把原始法球調成某一種 | 一段 chat 的 `action` |
| 取得該球 → 授予它的**基礎樹** | **授予技能樹**，見 `docs/knowledge/npc-and-chats.md`（該文件有「授予技能樹」一節）|
| **深化**該球（更深的節點／任務／聖殿）→ 解鎖它的**其餘樹** | 同上，分次授予 |

**「一球多樹 + 分次解鎖」讓法球本身有成長曲線**，
而不是拿到就一次給滿——這也是玩家在「多拿幾種球」與「把一種球練深」之間的取捨。

- **持有球數要有上限**，否則全拿光就沒有取捨。深化也要消耗，理由同上。
- **惡球威力強、推高 AC**；善球溫和、壓低 AC。這是 build 決策的核心。
- 每棵樹 3–5 個天賦。**單棵不要做成滿編職業樹**——量太大且會和既有職業打架。
  深度靠「多棵樹」給，不靠「單棵很長」給。

⚠️ **21 球 × 2–3 棵 = 40–60 棵樹**，這是很大的量。
但它是**高度重複、格式一致**的量，正好適合弱模型照範本量產——
前提是[03](03-content-model.md) 的 `spheres.lua` 格式先定案，且**先做完一整球當範本**。

## 4. 宗教

全部教團（[01 §4](01-world.md)），每個：

- 一棵教團技能樹（3–5 個天賦。教團只有一棵，**多樹是法球的特權**）
- 加入／叛教走 chat；同時只能屬於一個教
- 影響 AC 的方向與速率
- 決定各文明 NPC 對你的態度

**陣營用 ToME 既有的 faction／reputation 機制**，不要自己造一套。

## 5. 地獄地形與四騎士

| 東西 | 做法 | 風險 |
|---|---|---|
| **地獄地形** | AC≥80 後，世界地圖上的格子分批換成地獄版地磚（換 `image` 與遭遇表）| ⚠️ 自訂地面**不要繼承 `base="GRASS"`**，`nice_tiler` 會 100% 換掉你的圖（`worldmap-parts/03` §8 已記，本 repo 踩過）|
| **四騎士** | 每個是一隻具名的高難度 actor，放在一個會在世界地圖上出現的入口／遭遇 | 「遊蕩」若太難做，**退化成固定地點的 boss 即可**——不要為了這個卡住整期 |

> **四騎士的「遊蕩」是加分項不是必要項。** 第一版做成「AC 到門檻，地圖上長出一個新入口」
> 就已經達成設計目的（世界隨數字改變）。真正的移動 AI 留到後期。

## 5.5 軍團 → 團隊 → 個人：敵人的尺度跟著地圖的尺度走 ★

**✅ 2026-08-06 使用者拍板。** 這是本設計最漂亮的一處對齊：
**三層地圖，對應三種敵人尺度**，每一層的「遇上」都是往下一層走。

| 層 | 上面的敵對實體 | 遇上它會怎樣 |
|---|---|---|
| **L0 大世界地圖** | **軍團**（唯一在上面遊蕩的東西）| **不是打一場仗**——進入一張臨時生成的 **L1 戰場** |
| **L1 中層區域地圖** | **團隊**（該軍團拆散在地圖上的小隊）；另有零星**個人** | 遇上團隊 → 進入 **L2**，打一場類似原版的遭遇戰。個人可以就地處理 |
| **L2 實際活動地圖** | **個人** | 一般 roguelike 戰鬥 |

> **一支軍團因此不是一場戰鬥，是一次作戰。** 你可以繞過去、挑軟的打、
> 打完幾隊就撤、或直搗指揮所。這比「撞上去 → 打一場 → 結束」有戲太多，
> 而且**完全複用已經要做的中層機制**，幾乎沒有額外成本。

### 5.5.1 遭遇軍團的流程

```text
在 L0 撞上軍團
  → 生成一張 L1 戰場（地形取自 L0 那一格，所以在森林遇上和在荒漠遇上不一樣）
  → 戰場上散佈 N 個團隊（N 與組成由該軍團的強度決定），可能還有補給營、指揮所、地形要點
  → 接觸某個團隊 → 進 L2 打一場實際遭遇戰
  → 打完回到 L1，繼續處理其他團隊，或撤退
```

**勝負不必全殲。** 幾種結束方式都要有：

| 結束方式 | 結果 |
|---|---|
| 擊潰足夠比例的團隊 | 軍團潰散，從 L0 上消失 |
| 攻下指揮所 | 同上，但更快、獎勵更好、風險更高 |
| 從 L1 邊緣撤退 | 回到 L0。**軍團還在，而且可能追** |
| 避戰穿越 | 潛行或高機動可以直接走過去 |
| 交涉 | 同派系、高聲望、或有正確的宗教身分時可以談 |

### 5.5.2 資料與規則

| 要素 | 做法 |
|---|---|
| L0 上的移動與生成 | **`wda`（world director AI）**——ToME 大地圖既有的機制 |
| 一支軍團 | 資料表一列：所屬派系、**團隊組成表**、強度、行為傾向、目的地 |
| L1 戰場 | 一張臨時 zone，**進 L1 配額**，且遭遇期間 `pinned`（打到一半不能被淘汰）|
| 團隊 | L1 上的一個 spot：兵種、數量、士氣 |
| 友方軍團 | 不是每支都要打——同派系或高聲望可通過、交易、甚至併行 |
| **AC 的影響** | 高 AC 時劫掠團與地獄軍變多、商隊與巡禮隊變少。**世界隨數字改變的第二個體感來源** |

### 5.5.3 這個架構天生支援「玩家指揮自己的軍團」

**使用者 2026-08-06 觀察到的：對，是有機會的。** 而且不必為它另建系統——
敵方軍團已經是「一支軍團 = 一組團隊 + 一個指揮所」，
玩家的軍團就是同一個資料結構換一個所有者。

| 要素 | 已經有的 | 還缺的 |
|---|---|---|
| 團隊組成 | 敵方軍團的組成表，同一格式 | 招募介面 |
| 在 L0 上移動 | `wda` 已經在做 | 玩家指令 |
| 在 L1 戰場上調度 | 戰場、團隊、指揮所都有了 | 下令與勝負判定的另一半 |
| 同伴隨主人成長 | 本 repo `tome-companions` 已實作過 | — |

**能做什麼**：僱傭兵團、教團的聖戰軍、自己文明的遠征軍；
帶著它在 L0 行軍，撞上敵方軍團時在 L1 上調度，自己仍然是場上一個角色。

⚠️ **但這不進 v1.0。** 理由是誠實的：它會把「一個 roguelike」變成
「一個 roguelike + 一個戰棋」，是**另一個量級的設計與平衡工作**，
而 v1.0 的目標是把產線跑順。

**現在要做的只有一件事：不要把路堵死。**
軍團與團隊的資料結構從第一天就寫成**與所有者無關**（`owner = "faction_id" | "player"`），
這樣未來要加只是補介面，不必重寫。**這條要寫進 v0.5 的驗收。**

⚠️ **一般荒野的 L1 上也有團隊在活動**（[§2.5.3](#253-具體長什麼樣)），
規則一致：**團隊要進 L2 才打，個人在 L1 就地處理**。
軍團戰場只是「團隊特別多、而且有目的」的 L1。

⚠️ **`wda` 有一個已知會崩的地雷**：只要設了 `data.wda = {script="X"}` 而
`/data/wda/X.lua` 不存在，`M/mod/class/GameState.lua:787` 會 `error(err)`，
**玩家第一步移動就崩**。要就完整提供，不要就整段別寫
（`docs/knowledge/worldmap-parts/03` §7 已複驗，行號搬運自該處）。

> 軍團層是「世界是活的」的主要來源，但**它不是 v0.1 的必要項**，
> 而且它**依賴中層機制先做好**——所以排在 v0.4 之後。

## 6. ⚠️ 複驗清單（到 Manjaro 開發機第一件事）

**前三項與第 7 項沒結論就不要開工。**
第 7 項（就地動態生成 zone）是 [§2.5](#25-區域-zone把空白格子變成一場冒險-) 整套機制的地基——
**它不成立的話，「無數的冒險」就得換一個做法**，越早知道越好。

| # | 要驗什麼 | 沒過的話 |
|---|---|---|
| **1** | AC 放 `game.party` 的**存檔往返**：存檔→離開→讀檔，數字與 `triggered` 表都要正確 | 改放 game state 或自訂序列化 |
| **2** | **角色死亡換新角色時，AC 該不該延續**？先確認 `game.party` 在新角色時的實際行為 | 這題會改變設計語意（見 [05](05-open-questions.md)）|
| **3** | 門檻觸發時**修改野外生成表**是否可行（怪物清單能不能執行期換） | 退成「進新 zone 才套用新表」 |
| **7** | **就地動態生成一張 zone 再進去**是否可行（[§2.5](#25-區域-zone把空白格子變成一場冒險-)的技術核心） | 退成「預先定義 N 種區域 zone 模板，依地形挑一個進去」——效果打折但一定能動 |
| **8** | 臨時 zone 的**存檔、LRU 淘汰、刪除**是否可行（ToME 的 persistent zone 存成 `.teaz`，執行期刪掉要驗） | 改成不進存檔的純臨時（會失去「回去東西還在」）|
| 4 | 授予技能樹在**非本 addon 職業**身上是否正常（玩家可能是任何職業） | 縮成給天賦而非整棵樹 |
| 5 | 世界地圖格**執行期替換地磚**是否會被存檔記住（zone 是否 persistent） | 改成進場遷移 hook（歐拉麗踩過同款，`SESSION-LOG` 有記）|
| 6 | 新 worldmap zone 的**連通性**：登陸點到每個文明入口，逐格走一次（**不准只用 `changeLevel()` 跳**）| 改地圖 |

> 5 與 6 都是本 repo **已經踩過**的坑（歐拉麗據點入口被牆擋死、persistent zone 改地圖對舊存檔無效）。
> 這兩項不是新風險，是**已知一定會再踩一次**的地方。

## 7. 明確不做

- **不做 4X**：不建城、不外交、不科技樹。見 [README](README.md) 前提 2。
- **不做新職業**：build 軸是法球與宗教，不是再開一個 class。
- **不讓諸神出場**：設定裡盟約禁止諸神親臨——**設定本身就幫我們省掉做神明 boss 的工**。
- **不改 ToME 的升級與傷害核心**：AC 與法球都是加法式的疊加層。
- **不逐字搬 FFH 原文**：專有名詞沿用，描述與對白全部原創重寫。
