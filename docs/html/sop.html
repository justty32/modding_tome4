SOP／計畫文件

agent 該從哪裡進來、遇到不同意圖時該讀哪個工作流入口，以及目前未動工的下一步建置計畫。 本 repo 的主體就是 addon 開發本身（tools/、self_mods/、docs/knowledge/、 workflows/）；漢化、成品、引擎分析降為 sub_proj/，唯讀第三方素材在 vendor/。專案專屬規則集中在 AGENTS.md、workflows/addon-dev/ 與 knowledge/。

agent 該從哪裡進來
AGENTS.md
always-on 鐵律 → WORKFLOWS.md
依意圖派發 → 各工作流入口
如 addon-dev/README.md

做／改 ToME4 addon 時，WORKFLOWS.md 會指到 workflows/addon-dev/README.md—— 那份才是「做一個 addon」的權威 SOP（本站 工具鏈頁 只是它的導覽摘要）。

核心（日常會用到）

AGENTS.md

什麼時候讀：每次 session 一開始。always-on 鐵律（絕不在真桌面跑 t-engine64、 docs/analysis 不是權威、佈署目標等）與「先讀哪裡」路由表。

→ AGENTS.md

WORKFLOWS.md

什麼時候讀：不確定現在該用哪個工作流時。依「使用者想做什麼」對照到入口檔的派發表。

→ WORKFLOWS.md

INDEX.md

什麼時候讀：要確認 repo 佈局、某個東西該去哪找時。 三層地圖：主體／sub_proj/／vendor/，含唯讀真相層路徑。

→ INDEX.md

workflows/addon-dev/README.md

什麼時候讀：要做／改一個 ToME4 addon 時的權威 SOP。 含前置讀本、驗證管線圖、各關卡證明表、Done-when。

→ addon-dev/README.md

workflows/common/conventions.md

什麼時候讀：碰原始碼前。程式碼慣例、真相層優先序 （vendor/t-engine4 > knowledge/ > docs/analysis）、CODE_MAP 維護鏈、多 agent 並行規則。

→ common/conventions.md

PLAN-camp-and-isekai.md

什麼時候讀：要接著做營地系統進階（農作計時器）或歐拉麗異世界剩餘增量 （酒館招募、市集、眷族）時。含可直接照做的檔案結構、落點/回程/nice_tiler 等已知坑、建置序。

→ PLAN-camp-and-isekai.md
進度追蹤

SESSION-LOG.md

什麼時候讀：接手時看還有哪些跨工作流的 open 項（目前為空——各工作流自己的 session-log.md 也都無 open 項）。

→ SESSION-LOG.md

session_log/

什麼時候讀：要知道「最近幾次 session 具體做了什麼、踩了什麼坑」的一句話流水帳 （PAS 慣例，按月分檔封存）。mod 產物頁的狀態標籤即整理自此。

→ session_log/
頂層文件
文件用途
README.md專案簡介、30 秒上手、目錄地圖、三條鐵律
INDEX.mdrepo 佈局三層地圖：主體／sub_proj/／vendor/
AGENTS.mdalways-on 鐵律、本地專案規則、fresh clone 環境還原
WORKFLOWS.md依意圖派發到工作流的對照表
tools/README.md工具鏈決策表：我想做 X 就跑哪支、要多久
DEV-GUIDE.md被動參考：檔案／資料夾何時該拆分整理
WAIT_USER.md需要使用者親自做／驗證才能繼續的 open 項
SESSION-LOG.md跨 session 的 open 進度
