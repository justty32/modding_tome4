SOP／計畫文件

agent 該從哪裡進來、遇到不同意圖時該讀哪個工作流入口，以及目前未動工的下一步建置計畫。 這套骨架其實是從一個可移植的通用 agent 工作流模板（見下方「框架自帶文件」）導入的， tome4-modkit 專屬的內容集中在 PROJECT.md、AGENTS.md 本地段落、 workflows/addon-dev/ 與 knowledge/。

agent 該從哪裡進來
AGENTS.md
always-on 鐵律 → WORKFLOWS.md
依意圖派發 → 各工作流入口
如 addon-dev/README.md

做／改 ToME4 addon 時，WORKFLOWS.md 會指到 workflows/addon-dev/README.md—— 那份才是「做一個 addon」的權威 SOP（本站 工具鏈頁 只是它的導覽摘要）。

核心（日常會用到）

AGENTS.md

什麼時候讀：每次 session 一開始。always-on 鐵律（絕不在真桌面跑 t-engine64、 analysis/t-engine 不是權威、佈署目標等）與「先讀哪裡」路由表。

→ AGENTS.md

WORKFLOWS.md

什麼時候讀：不確定現在該用哪個工作流時。依「使用者想做什麼」對照到入口檔的派發表。

→ WORKFLOWS.md

PROJECT.md

什麼時候讀：要確認「這個專案的 v1 完成定義是什麼」「參照素材路徑」時。 列出 8 條可驗證的 Done-when 條件與唯讀真相層路徑。

→ PROJECT.md

workflows/addon-dev/README.md

什麼時候讀：要做／改一個 ToME4 addon 時的權威 SOP。 含前置讀本、驗證管線圖、各關卡證明表、Done-when。

→ addon-dev/README.md

PRINCIPLES.md

什麼時候讀：猶豫「這件事要不要走完整工作流」時。輕量使用原則、 Truth Layers 優先序（code > docs > generated/html）、多 agent 並行規則。

→ PRINCIPLES.md

PLAN-camp-and-isekai.md

什麼時候讀：要接著做營地系統進階（農作計時器）或歐拉麗異世界剩餘增量 （酒館招募、市集、眷族）時。含可直接照做的檔案結構、落點/回程/nice_tiler 等已知坑、建置序。

→ PLAN-camp-and-isekai.md
進度追蹤

SESSION-LOG.md

什麼時候讀：接手時看還有哪些跨工作流的 open 項（目前為空——各工作流自己的 session-log.md 也都無 open 項）。

→ SESSION-LOG.md

session_log.md

什麼時候讀：要知道「最近幾次 session 具體做了什麼、踩了什麼坑」的一句話流水帳 （PAS 慣例，上限 50 行）。mod 產物頁的狀態標籤即整理自此檔。

→ session_log.md
框架自帶文件（ModForge 可移植工作流骨架，非 tome4 專屬）
文件用途
README.md這套可移植工作流骨架本身的說明（來自 ModForge），非 tome4-modkit 專案簡介
DEV-GUIDE.md被動參考：檔案／資料夾何時該拆分整理
ADOPTION.md把此骨架導入其他既有 repo 的分階段方式
MAINTENANCE.md定期清理、session-log／CODE_MAP 維護規則
SYNC.md已導入 repo 如何跟模板更新同步
INIT-QUESTIONS.md新 repo 導入前的問答清單
TEMPLATE-MANIFEST.mdminimal／standard／full 三種導入模式各自的檔案清單
UNINSTALL.md移除／降級此骨架的策略
DOGFOOD.md實戰導入此骨架時的摩擦記錄與下一版候選
WAIT_USER.md需要使用者親自做／驗證才能繼續的 open 項
CHANGELOG.md此骨架本身的版本紀錄
